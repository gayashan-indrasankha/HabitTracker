# Evidence and career tracking (P3)

The **Evidence** view under Goals & Projects records learning, portfolio, interview, English, weight, and application evidence. Weekly Review summarizes recorded evidence for the selected calendar week. Today shows at most one due academic revision and one overdue application follow-up. These are separate from habit adherence and completed tasks; there is no combined readiness score.

## Academic topics

Each topic belongs to one of the existing university subjects. A practice record keeps its calendar date, practice type, optional correct/total answers, confidence, duration, and note. Both score fields must be supplied together, with a positive total and `0 <= correct <= total`. Unscored explanations count as practice, not as a scored result. Existing subject assessment grades remain user-entered outcomes.

The displayed indicator is **Not assessed** without practice; **Needs review** if the latest scored attempt is below 70% or the user-set revision date is due; **Demonstrated mastery** only when the user selected that status and at least two scored attempts reached 80%; otherwise it is **Practising**. This is a transparent activity indicator, not a grade or independent certification. The practice log and dates remain intact if the topic status or revision date changes. Weekly accuracy divides the sum of correct answers by the sum of questions on scored attempts, rather than averaging percentages. A due revision is a suggestion based on the chosen date.

## Portfolio milestone quality

Criteria attach to existing milestone tasks and are optional per milestone. The user marks each criterion met or unmet and records a separate review with date, reviewer label, references, and notes. **Meets criteria** requires at least one criterion and all current criteria marked met; a completed task alone does not satisfy it. A later criterion change flags the accepted review for re-review. Each review saves an immutable criteria snapshot in review history, while the current review remains editable. Links and labels are user-provided evidence references; LifeOS does not inspect or certify external repositories.

## Interview and English assessments

Interview topic categories and role targets are editable. Practices retain the prompt, type, duration, optional explicit correct/total result for scored questions, strengths, weaknesses, and four self-rated rubric dimensions: technical accuracy, approach, clarity, and trade-offs. Scored results require both fields, a positive total, and correct no greater than total. A rubric score of 1 means the user cannot yet explain or solve it, 3 means partly correct with prompting, and 5 means accurate, clear, and independent. Any dimension at 2 or below, or written weakness, identifies a weak session. The next-practice suggestion names a topic with a recorded weakness and explains why; topics without practice are counted separately. Optional external rating is separately labeled as user-entered; no external assessment is verified. A follow-up becomes an ordinary linked task and can be created once per practice.

English sessions record type, topic, minutes, reflection, and optional 1–5 ratings for fluency, grammar, clarity, pronunciation, and confidence. For each dimension, 1 means frequent difficulty, 3 means generally understandable with noticeable gaps, and 5 means consistently clear in that session. Ratings are self-assessed unless the user names a reviewer; naming one is still a user-entered claim. The recent 180-day view compares the first and latest **rated days** per dimension; multiple ratings on one day are averaged, and missing dimensions show no assessment or comparison. Weekly Review reports recorded minutes, the lowest average rated dimension, and recent corrections. The grammar log keeps original and corrected expressions, category, and reviewed state. Practice minutes never imply fluency or grammar accuracy. No audio or automatic language assessment is stored.

## Actual body weight

Weight uses existing `metric_entries` records in kilograms. Entries can be corrected or removed with confirmation; other metric types are unaffected. Multiple measurements on one date are averaged into one daily value. A calendar-week average is the arithmetic mean of that week's measured **daily values**, using the user's configured week start. Missing days and weeks are omitted; a missing week has no value. Each displayed week reports its own measured-day count and marks fewer than three days as **Limited data**. The latest measured week is compared with the immediately preceding calendar week only when both have data; a gap does not imply a continuous weight trend. Weekly Review uses the same adjacent-week comparison. Change from baseline uses the first recorded measurement (or an available earlier baseline point); progress to the current target is `(latest weekly average - baseline) / (target - baseline)` when the target exceeds baseline. It may be below 0% or above 100%. The chart plots recorded daily values and the target reference; weekly averages appear in the adjacent text and Review. No missing measurements or nutrition advice are generated.

## Internship pipeline

A saved opportunity is not submitted. Creating an application with an explicit application date starts at Applied; otherwise the user records a transition from Saved. Each stage change is an append-only history row with a timestamp and previous/new stage. The application record stores the current stage for filtering; editing its details does not silently advance it. Submitted counts require a recorded application date. Active counts include Applied, Online assessment, Technical interview, HR interview, and Custom; offers and rejections remain in history. Follow-up dates are user-entered, and a linked ordinary task can be created once per application. No messages, submissions, scraping, or employer contact occur.

## Storage, privacy, and checks

Migrations `0011`–`0013` add P3 tables, review history, and optional interview score fields; they are additive to P0–P2. Server actions authenticate, validate input, check ownership, and use composite owner foreign keys. Application stage changes and task creation use transactions; stage history is preserved. Practice and chart queries are date bounded on the Goals evidence view. JSON backup includes the P3 records and private fields, so store exports privately.
