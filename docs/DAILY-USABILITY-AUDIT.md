# Daily usability audit

Audit date: 2026-10-09. This review uses the current `main` working tree. The default home remains `/dashboard`.

Current preference: Today is task based. Its schedule card, session prompt, and session-dependent lighter-day copy were removed. Focus tasks, habits, notes, and tomorrow's priorities remain. Existing time blocks and their history are still available in Week. The session-related findings and checks below record the earlier iteration of this audit.

Baseline: `npm test` passed 68 tests, `npm run lint` passed, and the isolated setup browser test passed before edits. Problems below are grounded in the named code paths; they are not estimates of user time.

Today now offers one optional **Show less today** button when there are multiple unfinished focus tasks. It shows one task while keeping the others saved. **Show full day** restores the full task list. An active lighter view still shows its reset button even when nothing is hidden. The three-mode panel, small-action form, and Today schedule card were removed; previously saved data remains stored.

The next-action prompt follows the tasks actually shown in the lighter view. Sessions and their history remain in Week. After a task is assigned to a priority slot, the search closes and resets so the user can see the updated Today list immediately.

Observed interaction counts in the browser test: assigning a priority uses **Add to Today â†’ Add to slot** (two button activations after choosing the task), planning tomorrow uses **Plan tomorrow â†’ Add to slot**, showing less uses one button activation, and the short review uses two answers and one submit. No elapsed-time or query-count improvement was measured.

## Verification and limits

- Baseline: 68 unit tests passed; lint passed; isolated first-use browser test passed.
- After changes: 70 unit tests passed; TypeScript, lint, isolated first-use and daily browser tests, the existing scheduling and two-user planning browser tests, the tracker browser test, and the production build passed. Each browser run uses a fresh PGlite database and a fixed test instant. Together they check registration, setup idempotency, dashboard redirect, priority start, linked completion, weekly adjustment, time off, Minimum mode persistence, note and short review persistence, weight entry, habit toggle persistence, account isolation, and a 390-pixel viewport. The tracker test first failed under the runner's October 9 default because it expects October 8; it passed when rerun with its declared fixture date. No product code changed in response to that mismatch.
- No database migration was added. Historical tasks, occurrences, priorities, and reviews retain their existing schema and meanings.
- Local PostgreSQL browser verification was unavailable because `HABITFLOW_TEST_ADMIN_URL` was not configured. The changed Drizzle action uses the existing transaction and user-scoped query patterns; PostgreSQL behavior remains unverified in this run.
- Gym habits, gym sessions, and evidence assessments do not share a canonical completion identity. Automatic propagation among them would risk recording facts that did not happen, so they remain deliberate independent check-ins.
- The audit did not measure real-world two-minute or fifteen-minute completion targets. Those require observed use with realistic personal data and timing.
